# 读空气

让 AI 帮你读懂互联网的“空气”。

“读空气”取自日语**空気を読む**——察觉一个环境里的情绪、氛围与言外之意。互联网上的讨论空间同样有自己的空气：一个页面表面上只是文字，读起来却可能是轻松温暖的，也可能是紧张的、荒诞的，或者已经充满火药味。

已有工具大多在判断内容是什么、情绪是正面还是负面、某句话是否具有攻击性。读空气关注的是另一件事——**整个空间现在是什么感觉**。它不判断谁对谁错，也不替用户决定是否参与，只是提供一个额外的观察维度。

## 第一阶段

第一阶段只回答一个问题：

> **这个网页现在到底有多大火药味？**

输出为 0～100 的冲突与敌意程度，配一句简短的空气判断。第一阶段不追求完整的空气模型，只验证最核心的假设——用户是否认为“让 AI 帮自己读空气”有趣、有价值。因此它刻意保持简单，以尽快接触真实用户。

衡量标准同样简单：用户看到结果后，会不会产生这样的反应——

> **“卧槽，确实。”**

## 产品形态

```text
浏览器扩展  ──▶  后端服务  ──▶  大模型
```

扩展负责读取当前页面、接收用户操作、展示结果；后端负责整理内容、组织分析、校验结果。大模型属于外部能力，不构成产品自身的业务核心。

## 开发

仓库为前后端同仓结构。后端基于 Java 与 Spring Boot，扩展基于 TypeScript 与 Vite。

```bash
# 后端
cd apps/backend
ATMOSPHERE_LLM_API_KEY=<模型密钥> mvn spring-boot:run

# 扩展
cd apps/extension
npm ci
npm run build
```

扩展构建产物位于 `dist/`，在 `chrome://extensions` 中以“加载已解压的扩展程序”载入。

后端按整洁架构分层组织代码，以模块公开契约隔离模块间依赖。协作规则与架构约束见 [AGENTS.md](AGENTS.md)。
