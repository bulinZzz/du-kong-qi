# 读空气

让 AI 帮你读懂互联网的“空气”。

“读空气”取自日语**空気を読む**——察觉一个环境里的情绪、氛围与言外之意。互联网上的讨论空间同样有自己的空气：一个页面表面上只是文字，读起来却可能是轻松温暖的，也可能是紧张的、荒诞的，或者已经充满火药味。

已有的工具大多在判断内容是什么、情绪是正还是负、某句话是否具有攻击性。读空气关注的是另一件事——**整个空间现在是什么感觉**。它不判断谁对谁错，也不替用户决定要不要参与，只是补上一个新的观察维度。

## 第一阶段

第一阶段只回答一个问题：

> **这个网页现在到底有多大火药味？**

结果是 0～100 的骂战激烈程度，配一句简短的空气判断。它不试图建立完整的互联网空气模型，而是先验证最核心的假设——人们是否觉得“让 AI 帮自己读空气”有趣、有价值。因此第一阶段刻意保持简单，并尽快接触真实用户。

衡量成败的标准也很简单：用户看到结果后，会不会想——

> **“卧槽，确实。”**

## 产品形态

```text
浏览器扩展  ──▶  后端服务  ──▶  大模型
```

扩展负责读取当前页面、接收用户操作、展示结果；后端负责整理内容、组织分析、校验结果。大模型属于外部能力，不构成产品自身的业务核心。

## 开发

仓库采用单仓库管理前后端。后端基于 Java 与 Spring Boot，启动方式：

```bash
cd apps/backend
mvn spring-boot:run
```

后端按整洁架构分层组织代码，用模块公开契约隔离模块之间的依赖。协作规则与架构约束见 [AGENTS.md](AGENTS.md)。
