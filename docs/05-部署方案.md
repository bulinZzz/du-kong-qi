# 读空气 部署方案

后端为无状态可执行 jar：不依赖数据库，也不将讨论内容落盘。部署只需一台最小规格的云主机。

## 一、打包与运行

```bash
cd apps/backend
mvn -DskipTests package
ATMOSPHERE_LLM_API_KEY=<模型密钥> java -jar target/*.jar
```

| 环境变量                       | 说明                                                                            |
| -------------------------- | ----------------------------------------------------------------------------- |
| `ATMOSPHERE_LLM_API_KEY`   | 模型服务的密钥，必填                                                                    |
| `API_GUARD_ALLOWED_ORIGINS` | 允许的请求来源，上线时填扩展自身的来源 `chrome-extension://<扩展 ID>`；留空则不校验来源，启动时打一条警告               |
| `API_GUARD_PER_IP_PER_MINUTE` | 单个来源 IP 每分钟的请求数                                                              |
| `API_GUARD_DAILY_LIMIT`    | 全部请求的每日上限，超出后不再受理                                                             |

限流两项的默认值与取值理由见 [application.yml](../apps/backend/src/main/resources/application.yml) 的注释，该处为唯一来源。

## 二、反向代理与 HTTPS

反向代理**必须**写入 `X-Forwarded-For`。应用据此识别来源 IP（对应配置 `server.forward-headers-strategy`）；缺失该头时，来源 IP 一律取到代理地址，按 IP 的限流会误伤全部调用方。

Nginx 先只声明 80 端口。`$remote_addr` 为直连对端地址，以覆盖方式写入，使客户端自带的值不参与取值：

```text
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

安装 `nginx`、`certbot` 与 `python3-certbot-nginx` 后执行 `sudo certbot --nginx -d api.example.com`：certbot 据此补全证书与 443 监听，并将 80 改为跳转；证书续期由其附带的 systemd timer 承担。

## 三、首次上线步骤

1. 购买域名并解析到服务器；
2. 部署 jar（systemd 或 Docker），配置模型密钥；
3. 配置反向代理与 HTTPS，确认 `https://<域名>/privacy` 可访问；
4. 将扩展来源填入 `API_GUARD_ALLOWED_ORIGINS`；
5. 生成上传包：`$env:BACKEND_ORIGIN='https://<域名>'; npm run package`，产物位于 `apps/extension/release/`；
6. 将 zip 上传至 Chrome 开发者后台，隐私政策地址填写 `https://<域名>/privacy`。

扩展 ID 在上传首个版本后固定，因此第 4 步与第 6 步的先后不可调换。
